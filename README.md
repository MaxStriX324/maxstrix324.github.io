## GitHub About и темы репозиториев

Единый список рекомендуемых `description`, `homepage` и `topics` для семи актуальных репозиториев: [`data/github-about.json`](data/github-about.json). Инструкция: [`docs/GITHUB_ABOUT.md`](docs/GITHUB_ABOUT.md).

```bash
python scripts/sync_github_about.py --show
python scripts/sync_github_about.py --check   # требуется gh auth
python scripts/sync_github_about.py --apply   # только по решению владельца
```

`--apply` использует установленный GitHub CLI и учётную запись владельца. Коммит документации **не изменяет GitHub About автоматически**; подключённый к чату GitHub API не имеет действия для записи этих полей.

## Единый реестр лабораторных проектов

Источник данных для **пяти публичных лабораторных утилит** — [`data/lab-tools.json`](data/lab-tools.json).
Из него скрипт [`scripts/sync_lab_catalog.py`](scripts/sync_lab_catalog.py) формирует:

- карточку лаборатории на главной `index.html`;
- пять карточек на странице `project/index.html`;
- пять подробных карточек `project/lab-automation/index.html`;
- раздел «Автоматизация лаборатории» в **отдельном профильном репозитории** `MaxStriX324/MaxStriX324`, если передать путь к его README.

После обновления `data/lab-tools.json` клонируйте **оба** репозитория в соседние каталоги:

```bash
git clone https://github.com/MaxStriX324/maxstrix324.github.io.git
git clone https://github.com/MaxStriX324/MaxStriX324.git
cd maxstrix324.github.io
python scripts/sync_lab_catalog.py --write --profile-readme ../MaxStriX324/README.md
python scripts/sync_lab_catalog.py --check --profile-readme ../MaxStriX324/README.md
python -m unittest discover -s tests -p "test_lab_catalog_sync.py" -v
```

Скрипт изменяет только участки между маркерами `LAB_TOOLS_GENERATED_START` и `LAB_TOOLS_GENERATED_END`. Остальная разметка сайта и профиль GitHub остаются без изменений. Команда без аргументов выполняет только проверку, ничего не записывая. Создавайте отдельные коммиты/PR в каждом репозитории: Python-скрипт **не публикует и не пушит файлы автоматически**.

GitHub Actions проверяет соответствие **карточек сайта** реестру в PR. После публикации в `main` дополнительно сверяет профильный README в ветке `main` другого репозитория. Поэтому при первом включении системы **сначала следует принять PR профиля, затем PR сайта**; иначе межрепозиторная проверка покажет рассинхронизацию. Запуск Actions зависит от доступности GitHub runner и квоты минут.

Остальные страницы — описания аппаратных проектов, фото, сведения о готовности, аналитика и sitemap — поддерживаются отдельно. Для нового инструмента с собственной страницей нужно добавить её HTML и URL в `sitemap.xml`; скрипт не создаёт такие страницы автоматически и не подменяет проверки электрооборудования.

## Аналитика личного сайта

Все HTML-страницы подключают `assets/analytics.js`. Для личного сайта настроены отдельные счётчики: GA4 `G-L18YE7WY1F` и Яндекс.Метрика `113706082` (не путать с 900pyk.club). Аналитика запускается только после явного согласия посетителя. Согласие можно отозвать в футере, тогда страница перезагружается. Для отчётов по переходам на репозитории в Метрике отдельно зарегистрируйте JavaScript-цель `github_repository_click`, в GA4 при необходимости зарегистрируйте пользовательский параметр события `repository`. Режим Вебвизора и запись сеансов выключены.
