# GitHub About: description, homepage and topics

Сайт портфолио и README обновляются через GitHub, но **поля About и topics являются настройками самого репозитория**, а не содержимым README. Для них подготовлен единый список `data/github-about.json` и локальная команда синхронизации.

## Команды для владельца репозиториев

Нужны Python 3.10+ и [GitHub CLI](https://cli.github.com/) с доступом к репозиториям. Токены в код, файлы и переписку не копировать.

```powershell
gh auth login
python scripts/sync_github_about.py --show
python scripts/sync_github_about.py --check
python scripts/sync_github_about.py --apply
```

Для одного репозитория, например Rigol:

```powershell
python scripts/sync_github_about.py --apply --only rigol-oscilloscope-sorter
```

`--show` не использует интернет и только печатает значения. `--check` читает GitHub API и завершится кодом 1 при расхождениях. `--apply` отправляет изменения в API через `gh auth`, а затем повторно читает и проверяет результат. Требуются права администратора соответствующих репозиториев.

Список включает сайт-портфолио, WorkBalance и пять лабораторных инструментов. Старые Telegram/VK-боты намеренно исключены: они больше не поддерживаются, их статус уже пояснён в README.

**Важно:** внесение этого скрипта в Git не изменяет поля About автоматически. Нужен однократный запуск `--apply` владельцем с авторизованным GitHub CLI. Скрипт нельзя включать в публичный CI с токенами администратора репозиториев.

## Рекомендации

- Держать короткое описание на английском: так проекты проще найти по технологии.
- Homepage указывать на соответствующую страницу портфолио, а не на несуществующую документацию.
- Topics выбирать по используемым технологиям и назначению, не заявляя неподтверждённые функции.
- После изменения README или функциональности проверять `--check`, когда изменились названия или фактические возможности.
